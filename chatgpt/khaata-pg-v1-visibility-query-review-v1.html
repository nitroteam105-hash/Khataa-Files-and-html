Visibility-Aware Query Layer v1

The access model now protects the read side as well as the command side.

Core rule: action authority and data visibility are evaluated independently. A staff member can be allowed to perform a task without automatically receiving access to every related financial or sensitive field.
Offline reality: this layer controls what the app presents from SQLite. It does not pretend that a remote role change instantly erases already-cached bytes from an offline device.

Read path

Coverage

The TypeScript layer includes visibility-aware repositories for tenant records, Collections, Expenses, staff cash custody and Staff & Access. It also includes reusable field-redaction helpers and an owner-only fallback consistent with sole-owner operation.

The accompanying test matrix explicitly covers the important case where an action is allowed but visibility is hidden, preventing us from accidentally coupling the two concerns again.
