Mobile Command Implementation Skeleton v1

The service API has now been pushed one layer deeper into concrete transaction-handler patterns.

Implemented in the skeleton: record payment, confirm joined, room transfer, explicit security application, and payment promise.
Still intentionally framework-neutral: no React Native/Android/Flutter database library is assumed. The handlers depend only on transaction, query, ID, clock, access, domain-event and outbox interfaces.

Transaction pattern

screen / view-model ↓ domain command handler ↓ validate business invariant ↓ permission gate ↓ BEGIN SQLite transaction ↓ domain writes ↓ domain-event history ↓ sync-outbox rows ↓ COMMIT ↓ return success to UI any failure before COMMIT → rollback everything

Important examples

recordPayment: rejects over-allocation before committing, preserves immutable receipt creation, and records staff cash custody inside the same local transaction.

transferRoom: ends the previous occupancy and creates the new one but deliberately performs no rent_terms mutation.

confirmJoined: only accepts an Upcoming tenancy and activates its planned occupancy explicitly; the date passing alone still does nothing.

applySecurityToDues: checks actual held security and outstanding obligation before appending an explicit application event.

recordPromise: writes promise history and sync work while deliberately creating no payment/allocation/ledger settlement.
