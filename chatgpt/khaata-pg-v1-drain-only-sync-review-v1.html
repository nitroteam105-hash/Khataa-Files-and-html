Drain-only Sync Lease v1

This closes the entitlement-expiry gap left intentionally open in the previous server build.

Product guarantee: an operation legitimately recorded while entitled or inside valid offline grace is not stranded merely because the entitlement disappears before reconnect. It may still upload in drain-only mode.
Security boundary: this design does not pretend a commodity phone can provide perfect forensic proof of the real-world time of an offline action. It provides a practical verified-server-time lease and explicitly states the remaining threat-model limit.

Offline time model

server verifies entitlement ↓ issue device lease: verified_server_time grace_expires_at entitlement keys config version ↓ device stores monotonic_at_verification ↓ while offline: effective server time = verified_server_time + monotonic elapsed device wall clock is not used to extend grace

Operation provenance

create local outbox operation ↓ verify lease contains required entitlement ↓ verify server-relative effective time ≤ grace expiry ↓ assign local sequence ↓ link previous operation hash ↓ hash canonical operation + lease provenance ↓ commit domain write + outbox provenance together

Reconnect after entitlement loss

current cloud_sync entitlement? ├─ yes → normal sync └─ no ↓ existing outbox item has valid lease provenance? ├─ no → reject / surface issue └─ yes → accepted_drain ↓ same typed server domain RPC ↓ ACK item ↓ continue until queue empty Drain-only never re-enables creation of new gated sync work.

Reboot / monotonic continuity

If the device loses trustworthy monotonic continuity, Khaata stops creating new paid-only offline operations until entitlement is re-verified. Already-created outbox entries are kept and may drain later. This is deliberately safer than falling back to the editable device wall clock.

Threat-model note

A hardware-backed device signing key can strengthen device binding, but it still does not universally prove when a human action occurred on a fully compromised/rooted phone. This V1 design therefore targets correctness, retry safety and casual clock-tampering resistance rather than claiming forensic timestamp guarantees.
