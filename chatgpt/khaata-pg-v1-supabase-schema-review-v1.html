PG V1 Supabase/Postgres Schema Proposal

This is the first concrete relational schema proposal derived from the frozen PG V1 data/event contract. Product semantics are source-backed; exact table/column names, indexes and triggers are implementation proposals.

Included: tables, foreign keys, check constraints, indexes, projection views, immutability triggers, migration order and an explicit RLS placeholder.
Not applied to Supabase. This is a reviewable migration proposal. RLS is intentionally not finalized until the shared account/business membership model is approved.

Important schema choices

Money: all amounts are bigint minor units; no floating point.
Offline IDs: UUID PKs accept client-generated values and also have DB defaults.
Monthly billing: obligations.deterministic_key is unique per business for idempotent offline-safe generation.
History: posted payments, receipts, security events, custody events and domain events are protected from UPDATE/DELETE by triggers.
Occupancy: partial unique indexes enforce one active assignment per tenancy and one active tenancy per capacity.
Security: agreed amount is stored separately from event-derived amount actually held.
Corrections: reversal/chargeback references the original payment rather than editing it.
Approval: approval rows authorize but do not stand in for the executed business event.
