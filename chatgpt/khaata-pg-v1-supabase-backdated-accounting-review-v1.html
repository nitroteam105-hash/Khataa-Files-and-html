Supabase Backdated Accounting v1

The backdated-accounting model now has a server implementation, server authorization boundary, and cross-device sync mapping.

New in this file: server tables, typed RPCs, immutable opening positions, append-only corrections, RLS, change-feed publication and mobile pull appliers.
Accounting invariant: opening figures never create fake payment, charge or security-event rows. They remain their own explicitly labeled accounting-start records.

Start-from-date server path

mobile opening position ↓ typed RPC ↓ business + action authorization ↓ validate tenancy + amounts ↓ insert tenancy_accounting_start ↓ insert immutable opening_financial_position ↓ append domain event ↓ change-feed triggers publish both records ↓ consume approval authorization if needed ↓ store idempotent sync ACK ↓ COMMIT

Cross-device behavior

device A commits opening position ↓ server accepts typed RPC ↓ sync_change_feed receives: • tenancy_accounting_start • opening_financial_position • domain_event ↓ device B pulls ↓ typed INSERT OR IGNORE appliers ↓ local statement projection immediately reflects opening figures

Correction behavior

The opening position itself cannot be updated or deleted. A correction is a separate append-only row with a type, signed amount delta, reason and timestamp. This preserves both the original accounting-start truth and the later correction.

Still proposed: this migration has not been run against the live Supabase schema. The permission keys set_opening_balance and correct_opening_balance should be added to configurable Staff & Access policy before rollout.
