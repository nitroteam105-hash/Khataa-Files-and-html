Approval Orchestration v1

This corrects the remaining local approval-transaction and approver-authority defects.

New in this file: approval-required commands now return a committed result instead of throwing after request creation; retries reuse the same pending request; approval authority is explicit; owner audit attribution uses user identity even when no staff membership exists.
Core invariant: requesting approval does not execute the action. Approving does not execute the action. Only the retried protected command performs the business mutation.

Transaction fix

protected command ↓ BEGIN SQLite transaction ↓ AccessGate.evaluate(...) ↓ permission = Needs approval ↓ create OR reuse approval_request ↓ return { status: "approval_required", approvalRequestId } ↓ COMMIT No exception. No rollback. No business mutation.

Approval path

approver opens pending request ↓ owner? ├─ yes → allowed └─ no → active membership + approve_requests = Allowed ↓ mark request Approved ↓ create one-use approval_authorization ↓ append approval decision history ↓ COMMIT Still no underlying domain mutation.

Execution path

requesting staff retries command + approvalAuthorizationId ↓ validate actor + action + target + expiry + unused ↓ perform business mutation ↓ append domain event ↓ consume authorization ↓ COMMIT If business mutation fails: whole transaction rolls back authorization remains unused
The new approve_requests permission is inserted as not_allowed by default for existing roles. Role-template defaults should be deliberately configured rather than silently granting approval authority to every active staff member.
