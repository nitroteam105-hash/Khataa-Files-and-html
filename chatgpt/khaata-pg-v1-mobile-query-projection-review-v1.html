Mobile Query + Projection Layer v1

The write side is now paired with a local SQLite read side for Home, Tenants, Tenant Detail and Collections.

Local-first read rule: normal screens read SQLite projections directly. They do not wait for Supabase.
Derived attention: Needs attention is computed from underlying business state. This build does not invent a generic reminders, dismiss, snooze or acknowledge table.

Home read path

SQLite domain tables ↓ projection views ├─ v_attention_candidates ├─ v_coming_up └─ v_business_pulse ↓ HomeQueries.getHome(businessId) ↓ Needs attention Coming Up Business Pulse

Business Pulse

Money fields use the current calendar month. Occupancy is point-in-time. Vacant beds returns null when capacity is unknown so the UI never misrepresents unknown capacity as zero. The permanent Pulse deliberately excludes expenses, profit, trends, charts, collection percentage and cash-with-staff.

Tenants

The repository exposes the frozen lifecycle filters Active, Upcoming, Moving out and Former, with Active as the default. Rows contain identity and room/bed plus only an operational exception when one exists; routine “all good” copy is omitted.

Important limitation kept visible

The current SQLite schema does not yet define tenant-requirement completion records, so the read model does not fabricate “missing required information” attention logic. That should be added only when the requirement-storage model is concretely specified.
