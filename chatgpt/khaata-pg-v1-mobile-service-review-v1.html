Mobile Repository + Service Contract v1

This is the API boundary between the Khaata mobile UI and the local-first domain/database layer.

UI rule: screens call domain services. They do not write SQLite directly and they do not depend on Supabase calls for normal operations.
Transaction rule: each business command owns its complete SQLite transaction, including domain records, audit/domain events and sync-outbox writes.

Service surface

BusinessService · PropertyService · TenancyService · BillingService · PaymentService · PromiseService · ChargeService · SecurityService · ExpenseService · CashCustodyService · ApprovalService · SyncService

Record payment

UI calls PaymentService.recordPayment(...) ↓ BEGIN SQLite transaction ↓ validate amount + allocations ↓ insert payment_event ↓ insert allocation(s) ↓ insert immutable receipt_snapshot ↓ cash method + staff collector? ├─ yes → insert cash_custody_event └─ no ↓ append domain_event(s) ↓ enqueue all sync_outbox work ↓ COMMIT ↓ return paymentId + receiptId ↓ UI immediately renders Paid

Room transfer

TenancyService.transferRoom(...) ↓ BEGIN ↓ end current occupancy assignment ↓ create new occupancy assignment ↓ append transfer event ↓ enqueue sync ↓ COMMIT rent_terms are untouched unless the user separately executes changeRent(...)

Permission boundary

Service commands check action permission before mutation. Allowed proceeds. Needs approval creates/returns an approval request rather than pretending execution occurred. Not allowed fails without domain mutation. Visibility remains a separate read concern.

Why this boundary matters

It keeps UI components simple, makes offline behavior deterministic, centralizes the frozen PG invariants, and gives Android/iOS implementations one place to enforce transaction safety. The same service call behaves the same whether the device is online, offline, reconnecting, or in drain-only sync mode.

The accompanying TypeScript file is intentionally framework-neutral. It can be implemented over React Native, native Android/iOS, Flutter/Dart equivalents, or another mobile stack without changing the domain contracts.
