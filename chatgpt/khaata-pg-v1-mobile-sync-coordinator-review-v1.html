Mobile Sync Coordinator v1

This connects the pieces we built separately: SQLite outbox, entitlement lease provenance, drain-only validation, and typed Supabase domain RPCs.

Result: a local command can now travel from committed SQLite truth to the correct server RPC without changing identity, losing dependency order, or bypassing permission/entitlement rules.
Still local-first: synchronization success is not what makes a payment, tenancy change or expense true on the phone. The local transaction already did that. Sync only reconciles shared server state.

Push path

pending SQLite outbox ↓ online? ├─ no → Offline └─ yes ↓ dependency ordering ↓ required entitlement currently active? ├─ yes → Normal └─ no → validate stored lease provenance ├─ invalid → Blocked └─ accepted_drain → Drain-only ↓ typed RPC dispatch ↓ server idempotent result ├─ accepted → ACK local outbox ├─ conflict → create sync_conflict ├─ permanent denial → Blocked └─ transient error → Failed + retry

Outbox migration

The SQLite outbox now stores the information needed to replay the exact operation: required entitlement, lease provenance, typed RPC name and arguments, server result, ACK time and conflict link. The same local outbox ID becomes the server operation_id, so retries cannot accidentally become new operations.

Drain-only behavior

When current cloud_sync is gone, only already-created outbox rows carrying valid lease provenance are eligible to continue. The coordinator validates that provenance first, then calls the same typed business RPC. It never restores the ability to create new cloud-sync-gated work.

Conflict behavior

A semantic server conflict does not delete or rewrite the local business event. The outbox row is blocked, a local sync_conflicts record is created, and explicit resolution can happen later.
