Backdated Accounting + Tenant Statement v1

This implements the two frozen onboarding paths for tenants who existed before Khaata accounting starts and gives Tenant Detail a proper statement projection.

New in this file: explicit accounting-start records, immutable opening financial positions, append-only opening corrections, net financial position views, and separate rent/charge vs security statements.
No fabricated transactions: opening outstanding, tenant credit and security actually held are opening figures. They are not disguised as historical payments, charges or deposit receipts.

Statement model

Opening position + rent / charge obligations + real payments + reversals + adjustments ↓ Tenant statement ↓ running rent/charge balance Separate: Opening security held + security receipts/applications/refunds ↓ Security statement

Corrections

The opening snapshot itself is immutable. If an owner entered the starting position incorrectly, Khaata appends an explicit correction with a reason. This preserves what was originally entered and how it was corrected later.

The “Bring existing history” path intentionally does not synthesize prior transactions. Historical rent, payments, charges and deposit activity must be entered/imported through their real typed domain flows so statement history remains truthful.
