Change Feed Integration v1

The server write path and server pull stream are now connected automatically and atomically.

New in this file: narrowly scoped typed PostgreSQL triggers publish each relevant domain row to sync_change_feed inside the same transaction that creates or changes it.
Not generic CDC: every trigger explicitly defines its entity type and transport payload. Khaata is not blindly serializing arbitrary table rows into a mutation channel.

Atomic publication

pg_record_payment(...) ↓ INSERT payment_event └─ trigger → feed row INSERT allocations └─ each trigger → feed row INSERT receipt └─ trigger → feed row optional INSERT cash custody └─ trigger → feed row INSERT domain_event └─ trigger → feed row ↓ COMMIT Any trigger/publication failure → whole RPC rolls back

Mobile transport adapter

The TypeScript SupabasePullApi now maps pg_fetch_changes results into the exact RemoteChange contract consumed by the PullCoordinator. It validates monotonic cursors and leaves merge policy to the resolver built in the previous step.

Allocation hardening

payment_allocations now gets explicit UPDATE and DELETE rejection triggers. Reversal effects are new allocation rows with allocation_effect=-1; the original allocation remains history.
Still proposed: none of these migrations has been executed against the live Supabase project. They must be reconciled with the actual deployed schema before applying.
